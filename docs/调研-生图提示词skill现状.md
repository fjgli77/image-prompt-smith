## 二、四个真正有分量的

### 1. ai-image-prompts-skill（最强的是"库"，不是"方法"）

- 11 类目、14,398 条，MIT，GitHub Actions 每天同步两次
- **强制带示例图**（`sourceMedia[0]`），无图直接跳过 —— 这条产品判断很对
- 两种模式：直接推荐 / 内容改编（喂文章 → 生成匹配 prompt）
- 代价：依赖 node + pnpm，首次要下载整库

**它解决的是"找一条别人验证过的 prompt"，不解决"我这个具体需求怎么写"。**

### 2. skill-prompt-generator（最接近"生成"，但重）

- 12 个领域 skill + 1246 元素库，按领域取样拼装
- 三模式：Portrait / Cross-Domain / Design
- 覆盖四平台语法（MJ / SD / DALL·E / Nano Banana）
- 自述 v2.0 把"数据库利用率从 40.3% 提到 79.9%"—— 说明 v1 有大量元素用不上

**问题：元素拼装容易出"正确但平庸"的词，缺"为什么这样写"的判断层。**

### 3. image-prompt（4.1k★，最轻）

- 一个需求出 4 条不同方向，纯文本，2.6 KB
- **优点**：给选择而不是给唯一答案 —— 这个交互形态值得抄
- **缺点**：没有平台语法、没有反向、没有诊断

### 4. 中文教程公式（传播最广，也最浅）

三套公式本质是同一个：

```
主体 + 场景 + 风格 + 光线 + 镜头 + 细节/画质
```

以及"四层"版：`主体层 + 风格层 + 构图层 + 限制层`。

**它们的价值是"教人别只说一句话"，局限是：**
- 不区分平台（同一条公式喂 MJ 和 SD，效果差一倍）
- 不讲冲突（写实 + 动漫照样往里填）
- 不讲诊断（出图不对怎么办，只有"删形容词"）
- 画质词当解药（`8K/超清/极致细节` 被反复推荐）

## 四、三个空位（本 skill 只填这三个）

### 空位 1：**"描述 → 结构化"的判断层，而不是"库 → 拼装"**

现有方案要么给库（检索），要么给元素（拼装）。缺的是**判断**：

- 这个需求该走叙事句还是标签串还是版式蓝图？
- 这句"高级感"该换成哪个光位？
- 这条为什么必须删掉"8k"？

本 skill 用**十一格 + 三层词级（专有名词 > 流派术语 > 通用形容词 > 主观评价）**做这层判断。

### 空位 2：**出图之后的诊断**

全网 14 个对象，**没有一个做"出图不对怎么办"**。它们的假设是"提示词写对了就出对了"，但真实工作流是：出图 → 不对 → 改 → 再出。

本 skill 的 **40 条症状码 + 排查树 + 三改法（换词/改句式/移位置）** 填的就是这一段。这个形态抄自短剧 skill 圈已验证的做法（`forest-laoli-h3` 的 D01–D50 症状码 + 排查树），移植到图像域。

### 空位 3：**可跑的机检**

现有 skill 全是 `SKILL.md`（纯提示词），没有一条能对用户的成品 prompt 做机械校验。

本 skill 带 `prompt_lint.py`：结构缺格、语义冲突、平台语法误用、画质词堆砌、动作过量、文字期望不匹配，六类问题输出 P0/P1/P2 + 0–100 分。**零依赖、单文件、可 `--json`。**

## 五、抄了什么，不抄什么

### 抄

| 来源 | 抄的点 |
|---|---|
| ai-image-prompts-skill | 类目按"用途"切（不是按风格切）；无样本不出货 |
| image-prompt (4.1k★) | 一次给多条方向，而不是一条改八遍 |
| skill-prompt-generator | 平台语法分家写，不混着教 |
| Nano Banana Pro 官方 | 七段式：交付物打头 + 末尾"禁止改动"段 |
| Seedream 5 官方 | 版式优先：版面结构排在风格形容词之前 |
| forest-laoli-h3（短剧） | **症状码 + 排查树**这个检索结构（形态，不是内容） |
| 中文教程公式 | 六段式的顺序（主体必须最前），保留为叙事句骨架 |

### 不抄

| 不抄 | 理由 |
|---|---|
| 10,000+ prompt 大库 | 与"生成"冲突；且要 node + 定期同步，破坏零依赖 |
| 元素随机取样拼装 | 出"正确但平庸"的词，用户还是要改 |
| 画质词解药论（8K/超清/杰作） | 实证是增加噪点风险，不增加清晰度 |
| 万能反向词 200 条 | 边际效应在第 15 个之后转负 |
| 只做"生成/优化"不做"诊断" | 真实工作流有一半时间在改 |
