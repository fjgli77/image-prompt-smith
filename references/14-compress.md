# 压缩：把散文压掉，把结构留住

> 用户说"太长了"的时候走这条。**压缩不是删信息，是删语言的形状。**
> 证据在前，刀法在后。别凭手感砍。

---

## 一、五条证据（先看数字，再动刀）

| # | 来源 | 结论 | 对我们的意义 |
|---|---|---|---|
| 1 | **火山引擎·即梦 Seedream 4.6 接口文档** | prompt「最长不超过 **800 字符**，prompt 过长有概率出图异常或不生效」 | **这是硬墙**。超了不是变差，是可能直接报错 |
| 2 | **字节 Seed 官方提示词指南（Seedream 4.5）** | 建议「≤600 英文词 或 **≤300 汉字**」；官方说 4.5「需要比旧版更少的描述」 | 300 汉字是**建议上限**，不是起跑线 |
| 3 | **ByteDance Seed 论文《Scaling Properties of Text Conditioning in Visual Generation》**（arXiv 2607.29679） | 自然语言 prompt 随长度**快速饱和，最终低于最短 prompt**；新增文字"多在复述、解释、连接已有内容，没有补充新的视觉变量" | **长度不换质量**。加字≠加信息 |
| 4 | **DetailMaster benchmark**（19 个模型，含 GPT Image-1 / FLUX / SD3.5） | 长 prompt 失败**主要不是"忘了画"，而是 attribute binding 失败**——属性被绑到错误实体上 | 压缩要顺手治错绑：**一句一主体** |
| 5 | **arXiv 2504.01137（token 冗余研究）** | 移除冗余 token 后**性能保持，错误减少 21%**；语义泄漏可降 85% | 删冗余**只有收益没有代价** |

**四条补证（阈值侧，覆盖各平台）**

- **万相 wan2.6**：正向 prompt「长度不超过 2000 个字符，超过部分会**自动截断**」；负向 500 字符。
- **可灵 Kling**：网页端「字数不超过 **500 个字符**」；API 端英文 ≤5 万、非英文 ≤2.1 万——**同一家两个入口，上限差 40 倍**。
- **Midjourney v7**：描述部分「20–35 词最佳，超过 ~40 词开始混淆」；官方提供 `/shorten` 命令自查冗余词；V7 自带高质量，`8k / ultra detailed / award-winning` 一类词已属废词。
- **Flux.1 / Flux.2**：Flux.1 的 T5 窗口 512（schnell 256）+ CLIP-L 77，官方建议 30–80 词；Flux.2 窗口 32k，官方仍推荐 30–80 词。
- **SD 1.5 / SDXL**：CLIP 位置编码只有 77 个，**超出的部分静默丢弃**——所以"后半段写了但没画"不是模型不听，是根本没读进去。
- **Nano Banana**：官方给 150–200 词，但第三方实测**超过 ~100 词质量反降**；角色一致性块要压到 50 词内。
- 注意力机制侧：CLIP 类编码器每段 75/77 token 截断，**超出部分的形容词不是无用，而是会稀释真正重要的词**。

> **一句话总结证据**：模型吃的是"与像素绑定的结构化信息"，不是字数。所以压缩的对象是**散文**（解释、连接、复述、抒情），不是**结构**（主体、部件、数量、方位、光位、画幅）。这条结论对**所有平台**成立，只是各家上限不同。

## 二、四档长度（替换旧的三档）

| 档 | 中文字数 | 英文词 | 给谁 | 说明 |
|---|---|---|---|---|
| **S 极短** | ≤90 | ≤45 | MJ / 标签派 / 社媒封面 | 只留主体+材质+光+画幅 |
| **M 标准（默认）** | **150–280** | 60–90 | 即梦 / Seedream / 万相 / 可灵 / Nano Banana / Flux | 落在各家官方建议内 |
| **L 详细** | 300–480 | 100–140 | 设定稿 / 资产图 / 需复现细节 | **已略超多数平台建议**，交付时要说明可能漏项 |
| **禁** | 各平台硬上限 | — | — | 见下表，超了不是变差，是可能报错或截断 |

### 2.1 各平台实际上限（压之前先查这张）

| 平台 | 正向上限（硬） | 甜点区 | 负向放哪 | 权重语法 | 压缩时特别注意 |
|---|---|---|---|---|---|
| **即梦 / Seedream 4.5–4.6** | **800 字符**（官方：过长有概率出图异常或不生效） | ≤300 汉字 | 无独立负向框 → **正向化** | 括号权重基本无效 | 最严的一家，先按 800 卡 |
| **万相 wan2.6** | 正向 **2000 字符**（超出自动截断）、负向 500 | ≤300 字 | 独立 `negative_prompt` | 不需要 | 超 2000 是**静默截断**，尾巴全丢 |
| **万相 wan2.7** | 正向 5000 字符 | ≤300 字 | 独立 `negative_prompt` | 不需要 | 上限宽松≠该写长 |
| **可灵 Kling（网页）** | **500 字符** | ≤300 字 | 与正向混写 | 无 | 网页端比 API 严格得多 |
| **可灵 API** | 英文 ≤5 万字符 / 非英文 ≤2.1 万 | 仍按 300 字写 | 混写 | 无 | 上限极大，但长了照样掉元素 |
| **MJ v7** | 无硬上限 | **20–35 词**（<40） | `--no a, b`（单独参数） | `::` 可用，但少用 | 有 `/shorten` 自查；质量词堆砌反而减分 |
| **SD 1.5 / SDXL** | CLIP **77 token**（≈50–60 汉字），超出**静默截断** | 标签 40–75 词 | 独立负向框 | `(word:1.2)` 有效 | 主体与关键件必须进前 50–60 token |
| **SD3 / Flux.1** | T5 512（schnell 256）+ CLIP 77 | **30–80 词** | **无负向框** → 正向化 | 权重常降质，别用 | 自然语言成句优于标签堆 |
| **Flux.2** | 32k token | 30–80 词（复杂场景 80–300） | 无 | 不需要 | 窗口大不等于该写长 |
| **Nano Banana** | 很长 | 实测 **>100 词开始掉**；角色块 <50 词 | 末尾可写排除 | 无 | 先写"这张图的用途"再写画面 |
| **GPT Image / Ideogram** | 长 | 60–120 词 | 正向化 | 无 | 文字用引号，短于 5 词 |

### 2.2 一条原则：换平台只换"壳"，不换"核"

| | 是什么 | 换平台时 |
|---|---|---|
| **核** | 主体、结构件、数量、方位、光位、画幅 | **一个字不改** |
| **壳** | 字数上限、负向放哪、权重语法、语言 | 按上表替换 |

所以压缩**只做一次**（把散文压成结构），然后按平台改壳。
**不要**为每个平台重写一遍——那会引入属性漂移。

### 2.3 无负向框的模型怎么处理（四家：即梦 / Flux / GPT Image / Flux.2）

它们的"不要"会被当成画面内容读，甚至真的画出来。**逐条转正向**：

| 想排除 | 写成 |
|---|---|
| 不要文字水印 | `画面干净，表面无字` / `clean surface, unmarked` |
| 不要杂物 | `地面从画面边缘到边缘都是裸露混凝土` |
| 不要塑料皮肤 | `可见皮肤纹理与细毛孔` |
| 不要多人 | `画面只有一个人物，其余空间为空气与地面` |
| 不要现代建筑 | `画面全部为木构与石砌，无金属与玻璃` |

有独立负向框的（万相 / SD / MJ）：**把排除项全搬过去**，正向里一条不留。

**默认走 M。** L 只在"资产图、需要逐项复现"时用，且必须**分结构段**而非连续散文（论文的 Structured Prompt 结论：结构化长文本才有效，散文长文本无效）。

### 为什么 L 档要分段，不许写成流水句

```
【无效的长】她持剑而立，剑身修长优雅，线条流畅得仿佛一缕被清风凝固的云气，
又似一抹被摘下的月光，通体澄蓝宛如水晶雕琢，透着超凡脱俗的美感……（140 字，只有 2 个视觉变量）

【有效的长】三尺三寸直刃；剑脊笔直、一线高光不断；剑格镂空云纹呈飞鸟展翅；
握柄缠素白丝绦，顺时针；剑身通体澄蓝，半透明，内部有流光；剑首垂紫青剑穗。（80 字，7 个视觉变量）
```

**判据**：一句话里能数出几个"图上能指到位置"的变量。数不出来就是散文。

## 三、六刀（按可删性从高到低）

| 刀 | 砍什么 | 例 |
|---|---|---|
| **① 解释与连接** | "仿佛/宛如/给人一种…之感/整体透着…/既…又…" | 「似一缕被清风凝固的云气」→ 删 |
| **② 抽象品质词** | 华丽、精致、高级、绝美、震撼、优雅、大气 | 「华丽的金色铠甲」→「鎏金甲片，边缘磨白」 |
| **③ 重复形容** | 同一特征写两遍 | 「银白长发及腰」+「长发飘逸」→ 留前者 |
| **④ 逐件成句 → 顿号合并** | 同类部件不各占一句 | 三句变一句：`剑格镂空云纹、握柄缠素白丝绦、剑首垂紫青剑穗` |
| **⑤ 设定与故事** | 性格小传、来历、招式名、能力说明 | 「此剑乃师门传承，曾斩妖魔三千」→ 全删（模型不执行） |
| **⑥ 反向词搬框** | 正向里堆"不要X不要Y" | 有负向框 → 全搬；无负向框 → **只留 1–2 条最关键的**（过度负向会压掉有效细节） |

**第 ⑥ 刀有实测支撑**：同一任务移除 negative prompt 后 PSNR 从 15.01 → 23.03；删冗余描述后到 25.8（该组最优）。**堆反向词是净损失。**

## 四、红线（一个字都不许删）

1. **主体前 20 字**（分层优先级：主体 → 风格 → 构图 → 光 → 技术参数）
2. **用户点名的设计元素**：武器形制、指定件数、指定颜色、指定部位
3. **数量封顶**：恰好 N 柄 / 仅此四格 / 不增加 N+1
4. **方位与接触**：头顶正上方、离手悬停、垂至剑格下方两寸
5. **画幅与排除项**：3:4、无文字水印
6. **锚点**：脸型、发色、瞳色、头身比

砍到红线就停。**宁可超 20 字，不许丢一项。**

## 五、一句一主体（治属性错绑）

长 prompt 最常见的失败不是漏画，是**属性串台**：写了银发女主和黑衣男配，出来银发穿黑衣。

```
【易错绑】银白长发的女剑修与黑袍男修对峙，手持青碧长剑，衣袂翻飞
        （青碧长剑归谁？衣袂是谁的？）

【已解绑】女剑修：银白长发，月白广袖长裙。男剑修：黑袍，束发。女剑修右手持青碧长剑。
```

**规则**：一个短句只挂一个实体的属性组；多主体场景改成「主体：属性。主体：属性。」的并列式。

## 六、压缩流程（五步，可机检）

```
① 抽变量清单 → ② 逐句判结构/散文 → ③ 合并成 4–6 句 → ④ 回读核对 → ⑤ 报字数与删项
```

**① 抽清单**（心里列，不写进交付）：主体 / 件数 / 形制 / 颜色 / 材质 / 方位 / 光位 / 画幅 / 排除。

**② 逐句判**：这句能指到图上位置吗？能 → 结构句留；不能 → 删。

**③ 合并**：结构句压成 4–6 句，每句一个功能（形制 / 结构件 / 材质 / 状态 / 光 / 画幅）。

**④ 回读**：拿清单逐项对，缺一项补一句短的，不补一段长的。

**⑤ 报账**：交付时写一行——

```
压缩：1280 → 245 字（删解释句 6、抽象词 9、设定小传 1；锚点与数量封顶全留）
```

## 七、压缩前后对照（三个真实类型）

### 例 A｜仙侠飞剑立绘

**压缩前 620 字（片段）**
> 她是一位气质清冷出尘的剑修，银白色的长发如瀑布般垂落至腰际，在月光下泛着柔和的光泽。她手中握着一柄帝器级别的本命飞剑，剑身修长优雅，通体澄蓝宛如水晶雕琢，透着超凡脱俗的美感，仿佛一缕被清风凝固的云气。剑格呈飞鸟展翅状，造型十分精美，护住剑柄。剑柄缠绕着素白色的丝绦，触感温润防滑。剑首垂落着一枚精致的剑穗，紫玉与青丝交织，散发着微弱而精纯的灵气，令人一见便知绝非凡品……

**压缩后 168 字**
> 顶级院线级3D国漫风，PBR材质，3:4，九头身。帝器级本命飞剑，未出鞘通体暗哑无光。三尺三寸直刃，剑脊笔直一线高光；剑格镂空云纹呈飞鸟展翅；握柄缠素白丝绦顺时针；剑身通体澄蓝、半透明、内部流光；剑首垂紫青剑穗，垂至剑格下方两寸。剑悬于右侧一尺，剑尖朝下，无手接触。冷调逆光。无文字水印。

**删了什么**：抒情 4 句、抽象词 5 个（清冷出尘/优雅/精美/温润/绝非凡品）、重复形容 2 处（长发写了两遍）。
**留住了什么**：品阶、光规则、尺寸、五个结构件、剑穗位置、悬浮状态、画幅。—— **视觉变量从 3 个涨到 9 个。**

### 例 B｜玄幻武器设定卡

**压缩前 480 字** → **压缩后 210 字**：删掉「力量感扑面而来」「硬朗霸气」「极具代表性」等评价句与 IP 背景介绍，保留材质/颜色/造型/纹路/状态五段与四格排布。

### 例 C｜3D 国漫战斗 KV

**压缩前 900 字** → **压缩后 150 字**：删掉叙事过程（"她冲入敌阵，剑光四起，敌人纷纷倒下"），只留主剑 1 柄 + 虚影 8 柄的分层写法、剑域的环境响应、画幅与仰拍。

> **共同点**：删掉的全是"读起来很美、画不出来"的句子。

## 八、机检

```bash
python scripts/prompt_lint.py --file p.txt --platform seedream --length standard
python scripts/prompt_lint.py --file p.txt --platform kling    --length standard
python scripts/prompt_lint.py --file p.txt --platform wanx     --length long --json
```

- 档位阈值已按本文件 §二 更新；`--length` 选错会误报，别用 long 去检一条 200 字的词。
- **超平台硬上限单列告警**，与档位超限分开：即梦 800 / 万相 2000 / 可灵 500 字符。
- 无独立负向框的平台（即梦 / Flux / GPT Image / Nano Banana），机检会把"不要…"判成语法问题，按 §2.3 转正向。
- 分数只抓结构性漏项，**不评价文笔**；压完分数可能不变，但字数降了——这是预期行为。

## 九、三条纪律

1. **先压散文，再压结构**。顺序反了会丢设计。
2. **一次只压一版**，压完出图，对了再压下一版。别一口气把 600 字砍到 80 字。
3. **用户显式要求 > 本文件**。用户说"要长一点、要写全"，照做，只把散文句换成结构句，不硬砍字数。
