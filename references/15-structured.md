# 结构化提示词：把一条词变成一张可复用的卡

> 2026 年 GitHub 上跑得最快的一类项目（如 awesome-gpt-image-2，16k+ star）都在做同一件事：
> **把提示词从"一段文案"拆成"一组可填的字段"。** 项目自称 Prompt as Code——不是文采变好，是**可复用、可版本管理、可交给程序调用**。

---

## 一、什么时候该用卡，什么时候不该

| 场景 | 用散文（六句） | 用字段卡 |
|---|---|---|
| 一次性出图、随便看看 | ✅ | — |
| 系列图 / 同一角色多张 | — | ✅ 固定字段，只改变量 |
| 批量生产（几十上百张） | — | ✅ 可填表、可脚本生成 |
| 多人协作、要交接 | — | ✅ 谁都能读懂哪格是什么 |
| 交给 Agent / 工作流 | — | ✅ 机器能解析 |
| 探索风格、试方向 | ✅ 快 | — |

**一句话**：**散文是给人读的，卡是给流程用的。** 不要因为结构化很酷，就把每张图都写成 JSON——那是另一种形式的浪费。

## 二、三档粒度（按需要选，别一上来就写全卡）

### 轻卡（8 字段，覆盖 80% 场景）

```yaml
subject:    帝器级本命飞剑，三尺三寸直刃，离手悬停于人物右侧一尺
composition: 3:4 竖版，中景偏全身，剑与人物同框
style:      顶级院线级 3D 国漫，电影级 CG，PBR
light:      冷调逆光，主光左后，剑身一道窄高光
material:   刃面拉丝银灰，剑格镂空云纹，握柄素白丝绦
negative:   无文字、无水印、第二把剑、真人、Q版、赛璐璐
ratio:      3:4
note:       帝器常态无光，只在剑鸣时影响环境
```

### 中卡（12 字段，加人物与场景的可控项）

在轻卡基础上加：`character`（脸型/眼型/特征）、`costume`（材质三件套）、`space`（前景/中景/远景）、`vfx`（粒子三层）

### 全卡（20 字段，成套资产 / 团队交接用）

再加：`purpose`（这张图干什么用）、`camera`（景别/焦段/机位）、`palette`（三色）、`props`、`text`（图上文字，引号）、`constraints`（数量封顶）、`refs`（参考图编号与角色分工）、`version`、`owner`

## 三、字段含义（写卡前先对齐口径）

| 字段 | 回答什么 | 不许写什么 |
|---|---|---|
| `subject` | 画面里最主要的那一个东西 | 两个主体并列（会互相抢） |
| `composition` | 画幅 + 景别 + 主体位置 | "构图好看"这类评价 |
| `style` | 画风族 + 介质 | 混写两个族（PBR + 赛璐璐） |
| `light` | 光位 + 光质 + 色温 | 只写"柔光"不写方向 |
| `material` | 主材 + 质感 + 光泽 | 只写"皮革"这种名词 |
| `character` | 脸型 + 眼型 + 一处特征 | 写"绝美""精致" |
| `costume` | 主件 + 材质三件套 + 配色 | 逐件成句的长描述 |
| `space` | 前 / 中 / 远 + 遮挡 | 只写"背景是山" |
| `vfx` | 一层主 + 至多一层辅 | 粒子词堆三种 |
| `negative` | 要排除的，按部件点名 | 塞进 `subject` 里 |
| `ratio` | `3:4` / `16:9` 这种数字 | "竖版"（部分模型不认） |
| `constraints` | 数量封顶 | 只写数量不封顶 |

## 四、散文 ↔ 卡：互相转换（这是卡真正好用的地方）

### 4.1 散文 → 卡（抽变量，不改字）

拿一条成品词，逐句问"这句属于哪格"，塞进去；塞不进的，就是散文句，**删掉**。

```
散文：帝器级本命飞剑，未出鞘通体暗哑无光，唯剑鸣时方圆十丈草叶齐伏。
   → note: 帝器常态无光，只在剑鸣时影响环境
```

### 4.2 卡 → 散文（按六句拼）

```
① 形状与介质 ← style + subject
② 主体与服装 ← character + costume
③ 关键部位 ← subject 里的结构件
④ 动作与场景 ← composition + space
⑤ 光与镜头 ← light + camera
⑥ 参数与排除 ← ratio + negative + constraints
```

**同一张卡可以拼出中文壳、英文壳、短句壳**——这就是"一核多壳"的机读版。

## 五、一致性红利：卡的最大价值

系列图崩，八成是"每张都重写描述"。用卡之后：

```
固定字段：subject（角色）/ character / costume / style / light / ratio
可变字段：composition / space / vfx / note
```

**规则**：只动可变字段，固定字段逐字复制。**改了固定字段 = 换了一个人**，与铁律 26 同源。

批量时更简单：把可变字段做成表格的一列，一列一个版本，逐行出图。

## 六、跨平台壳（卡不变，只换输出）

| 平台 | 从卡输出成什么 |
|---|---|
| 即梦 / 可灵 / 万相 | 中文六句，删掉字段名，按卡顺序连成一段 |
| GPT Image | 英文自然语言段落，`purpose` 放第一句，`negative` 转正向句 |
| MJ | 英文短句 20–35 词 + `--ar` `--no` |
| SD / Flux | 英文标签串（SD 加权重、独立负向；Flux 不加权重） |
| 批量 / Agent | 直接交 YAML 或 JSON，不再转散文 |

**转换方向永远是单向的**：卡 → 壳。不要从壳反推卡，会引入理解偏差。

## 七、四个反模式

| 反模式 | 后果 | 改法 |
|---|---|---|
| 把自然语言长句塞进 `value` | 卡退化成散文，失去可填性 | 每个字段 ≤25 字，超了就拆格 |
| 字段互相冲突（`style: 写实` + `note: 动漫感`） | 模型和稀泥，出中庸图 | 冲突项合并到 `style`，只留一个族 |
| 全卡 20 字段全填 | 生成慢、改不动、还容易被截断 | 按 §二 选档，别默认全卡 |
| 没有 `negative` 格 | 排除项散落在正文，模型当内容读 | 单独立一格，按部件点名 |

## 八、一张完整卡（可直接改）

```yaml
purpose:     角色立绘，用于系列设定集
subject:     帝器级本命飞剑，三尺三寸直刃，剑首垂紫青剑穗
composition: 3:4 竖版，中景偏全身，剑悬于人物右侧一尺，剑尖朝下
style:       顶级院线级 3D 国漫，电影级 CG，PBR 物理材质
light:       冷调逆光，主光左后方，剑身一道窄高光
camera:      85mm，中景偏全身，背景虚化
character:   银白长发高束，冷白肤色，细长眼，左眼下泪痣
costume:     月白广袖流仙裙，银纹绦带，丝缎 + 银饰 + 玉
material:    刃面拉丝银灰，剑格镂空云纹哑光黄铜，握柄素白丝绦
space:       远景云海与浮空仙山，前景无遮挡
vfx:         银色剑气贴剑身外溢，边缘泛淡霜色（单层）
constraints: 恰好一把剑，不增加第二把
negative:    无文字、无水印、真人、Q版、赛璐璐、第二把剑
ratio:       3:4
note:        帝器常态无光，只在剑鸣时影响环境
version:     v1
```

## 九、与其他文件的关系

- 散文写法仍在主路径（`SKILL.md` ④ 拼装六句）；**卡是它的结构化投影，不是替代**
- 一致性纪律见 `character/text-only-consistency.md`（锚点块逐字复制）
- 跨平台壳见 `character/cross-model.md`，压缩见 `14-compress.md`
- 字段字数上限沿用压缩红线：单格 ≤25 字，全卡 ≤400 字
