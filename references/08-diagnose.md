# 08 症状码与排查树

> 出图不对时，**不要加词，先定位**。加词是最常见的错误修复方式——它会让画面越来越糊。
> 用法：看症状 → 查码 → 选一条改法 → **只改一处** → 重出。

---

## 一、三改法（所有码的通用工具箱）

| 改法 | 做什么 | 什么时候用 | 例 |
|---|---|---|---|
| **A 换词** | 用更具体的词替换模糊词 | 模型"理解偏了" | `高级感` → `低饱和 + 45° 侧逆光 + 大留白` |
| **B 改句式** | 改语序、拆句、加限定 | 模型"漏看了" | `一个女孩在森林里看书` → `主体：女孩，坐在树根上读书。环境：清晨薄雾森林` |
| **C 移位置** | 把关键信息前移或独立成段 | 模型"权重不够" | 把"不要文字"从末尾移到开头独立一行 |

**优先级：C → B → A**。位置问题最常见，改词代价最大（会引入新变量）。

## 二、排查树（先走这一棵，再看码表）

```
出图不对
├─ 主体没了 / 变了
│   ├─ 主体在提示词前 20 字内吗？ ── 否 → C（前移）
│   ├─ 主体描述是具体名词吗？ ── 否 → A（实体化）
│   └─ 场景/风格字数超过主体吗？ ── 是 → B（压缩背景）
├─ 构图不听话
│   ├─ 写了具体构图比例吗？ ── 否 → A（给百分比/分割比）
│   ├─ 主体与留白要求冲突吗？ ── 是 → B（改成"主体位于左侧 40%"）
│   └─ 平台是否不擅长布局？ ── 是 → 换 Seedream/GPT Image（见 03）
├─ 光不对
│   ├─ 只写了"柔和/明亮"吗？ ── 是 → A（补光位+光质+色温）
│   ├─ 同时写了两个光位吗？ ── 是 → B（删一个，保留主光）
│   └─ 时间与光矛盾（夜景+明亮）？ ── 是 → B（统一时间）
├─ 风格串味
│   ├─ 风格词 >3 个吗？ ── 是 → B（砍到 3 个）
│   ├─ 混了不同族吗？ ── 是 → B（指定主风格）
│   └─ 反向里缺隔离词吗？ ── 是 → A（补隔离反向，见 07）
├─ 画面太满 / 没留白
│   ├─ 写了留白比例吗？ ── 否 → A（给 25–35% + 颜色）
│   ├─ 背景元素太多吗？ ── 是 → B（删元素，加"背景简洁"）
│   └─ 用途需要留白吗？ ── 是 → 走 01 用途表重排版式
├─ 文字乱码
│   ├─ 平台文字能力够吗？ ── 否 → 转"假文字 + 后期"
│   ├─ 文案加引号了吗？ ── 否 → B（加引号 + 层级 + 位置）
│   └─ 字数 >8 吗？ ── 是 → B（砍到 4–6 字）
└─ 一致性差（系列图）
    ├─ 锚点块逐字复制了吗？ ── 否 → B（建锚点块）
    ├─ 固定 seed 了吗？ ── 否 → C（固定 seed + 只改一格）
    └─ 风格/光跨图变了吗？ ── 是 → B（风格段与光段冻结）
```

## 四、四个高频组合症

### 组合 1：D01 + D13 + D14（主体消失 + 太满 + 没留白）

**这是"文案型提示词"的典型崩法**：写了一大段氛围，主体没位置。

治：**先删一半**。只留 `形态 + 主体 + 一句场景 + 光 + 构图留白`。删完再出图，通常一次就对。

### 组合 2：D24 + D25 + D27（串味动画 + 塑料 + 假 HDR）

**这是"堆词型提示词"的崩法**：`masterpiece, best quality, 8k, ultra detailed, cinematic, anime style, photorealistic`。

治：**画质词全删，风格只留一个，加隔离反向**。这三个码永远一起出现。

### 组合 3：D17 + D21（光平 + 暗部死黑）

**这是"没说光位"的崩法**：模型用了默认棚拍平光，暗部自然糊死。

治：一条光配方解决（见 04 光位表）。

### 组合 4：D30 + D31 + D33（乱码 + 语种错 + 排版挤）

**这是"指望模型写中文海报"的崩法**。

治：**放弃图内文字**，改成留白 + 后期。这不是提示词能解决的问题。

## 五、迭代纪律

1. **一次只改一格。** 同时改三处，你无法归因。
2. **固定 seed。** 不固定 seed，变化里包含随机性，看不到改词的真实效果。
3. **改前拍照。** 把当前提示词存成 `v1` / `v2`，别看图回忆。
4. **三轮不成，换路。** 同一个码改三次还不行，说明方向错了（换平台 / 换风格族 / 换构图），不是词的问题。
5. **记录日志。** 见 `10-eval.md` 的迭代记录表。
